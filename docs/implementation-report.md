# YE-G 공식 홈페이지 1차 구현 보고서

검증일: 2026-10-12. 이 문서는 로컬 구현 결과이며 운영 배포 완료 보고가 아닙니다.

## 1. 기준본과 작업 범위

작업 전 로컬 `feature/refine-marketing-tool`은 `index.html`만 추적했고, HTML 변경과 API·캐릭터 리소스 및 백업이 미추적 상태였습니다. GitHub `main`의 HTML·API 2개·기존 리소스 2개의 blob 해시와 현재 파일이 일치함을 읽기 전용으로 확인했습니다. 이 일치는 파일 기준의 일치이며 운영 서비스의 모든 외부 의존성 정상 동작을 증명하지 않습니다.

`codex/ye-g-web-baseline` 브랜치의 `30f34d8` 커밋에 기존 HTML·API·필수 리소스 5개를 보존한 뒤 `codex/ye-g-official-homepage`에서 개발했습니다. 원래 브랜치와 백업 사본을 보존했습니다. 원격 Push·Vercel 배포·운영 환경변수 변경·패키지 설치는 하지 않았습니다.

## 2. 구현 결과

- `/`: 공식 메인. 서비스와 캐릭터 브랜드에 각각 독립적인 소개 영역을 배치했습니다. 히어로, 서비스 기능, 진단 흐름, 캐릭터 배경, 광주 로컬 활동 방향, 진단 CTA와 푸터를 포함합니다.
- `/diagnosis`: 기존 5단계 진단 HTML을 별도 문서로 분리했습니다. 직접 접속·새로고침이 가능합니다. 메인 CSS·JS와 진단 스크립트가 문서 단위로 분리됩니다.
- `/diagnosis/`: 같은 진단 문서로 연결합니다. API 요청은 기존의 절대 경로 `/api/diagnose`, `/api/market-data`를 유지합니다.
- 브랜드 색상은 CSS 변수로 관리하는 민트·크림 임시 팔레트입니다. 공식 색상·타이포그래피 가이드 확정 시 교체할 수 있습니다.
- 헤더 모바일 메뉴·키보드 포커스·본문 건너뛰기·영상 정지 버튼·동작 줄이기 설정을 지원합니다.
- 최신 영상 원본의 첫 프레임을 포스터로 사용하고, 진단 화면의 구형 이미지 5곳도 이 포스터로 교체했습니다. 캐릭터를 새로 생성하거나 재디자인하지 않았습니다.
- 문의 연락처는 아직 제공되지 않아 ‘문의 채널 준비 중’으로 안내합니다. 가짜 연락처나 작동하지 않는 문의 버튼을 만들지 않았습니다. 앱·굿즈·지역 콘텐츠는 준비 방향으로 표시했습니다.
- `/about`, `/local`, `/news`, `/app`, `/contact`는 아직 구현하지 않았습니다. 현재 내비게이션은 구현된 섹션 또는 진단으로만 연결합니다.

## 5. 최신 영상 4종

원본은 모두 3840×2160 HEVC Main10, BT.709, 24fps입니다. 제공받은 원본 파일은 SHA-256을 변환 전후 비교하여 불변을 확인했습니다.

| 순서 | 길이 / 프레임 | 원본 바이트 | 웹용 바이트 | 감소 | SSIM |
| --- | --- | ---: | ---: | ---: | ---: |
| 1 | 15.0417초 / 361 | 3,274,141 | 1,065,707 | 67.5% | 0.998535 |
| 2 | 15.0417초 / 361 | 3,396,420 | 1,102,136 | 67.6% | 0.998573 |
| 3 | 10.0417초 / 241 | 2,422,992 | 859,987 | 64.5% | 0.998631 |
| 4 | 10.0417초 / 241 | 3,101,233 | 970,853 | 68.7% | 0.998651 |

총 12,194,786 → 3,998,683바이트(약 67.2% 감소). H.264 High 4.1, yuv420p 8비트, 1920×1080, 24fps, 오디오 없음, faststart입니다. 인코딩은 전체 16:9 프레임과 재생 순서·프레임 수를 유지합니다. 10→8비트 변환 및 손실 압축이므로 픽셀 완전 동일을 주장하지 않습니다. 색상 보정·배경 제거·원본 크롭은 하지 않았습니다.

SSIM은 원본을 동일한 1080p로 축소한 기준과 비교한 값입니다. 전체 1,204프레임의 축소 윤곽 경계 검사를 통과했고 대표 프레임도 시각 검토했습니다. 윤곽 검사는 밝기 임계값을 사용하므로 모든 희미한 픽셀에 대한 수학적 보장은 아닙니다. 얼굴·구슬·손·발을 포함한 주요 형태는 중앙 정사각형 영역 안에 있습니다.

CSS는 `aspect-ratio: 1 / 1`, `overflow: hidden`, `object-fit: cover`, `object-position: center`를 사용합니다. 표시 높이를 유지하면서 양쪽만 동일하게 가립니다. 파일 자체는 16:9입니다.

영상 목록과 재생기를 분리했습니다. 두 video 레이어 중 대기 레이어가 다음 영상을 미리 읽고, 첫 프레임이 준비된 뒤 표시를 전환합니다. `ended` 이벤트로 1→2→3→4→1을 반복하며 각 video에 loop를 사용하지 않습니다. muted·playsinline, 자동재생 실패/로딩 실패 시 최신 정지 이미지, 동작 줄이기·페이지 숨김·화면 밖 일시정지를 지원합니다.

플레이어 자동 테스트에서 2회 연속 순환, 일시정지·재개, 음소거, 동작 줄이기, 재생 실패·재시도를 검증했습니다. 실제 인앱 브라우저에서도 영상 1 시작 및 2→3→4→1→2 전환을 관찰했습니다. H.264 파일을 선택해 HEVC 의존성을 제거했으나 실제 Safari/iPhone/Chrome 기기 검증은 배포 전 별도 수행해야 합니다.

## 6. 남아 있는 위험과 권장 조치

1. **공개 AI API 호출 제한:** 기존 서버에는 사용자별 호출 횟수 제한·전체 비용 한도·강한 요청 크기/문자열 길이 제한이 없습니다. 홈페이지 노출 증가 전에 서버 입력 한도, 요청 제한 저장소 또는 플랫폼 제한, 공급자 예산 한도, 429 안내를 작은 별도 변경으로 추가하는 것을 권장합니다. 이번에는 서버 동작·운영 설정을 바꾸지 않았습니다.
2. **빈 좌표 처리:** 기존 `api/market-data.js`의 `Number('')`는 0이 되므로 빈 문자열을 유효 좌표로 잘못 해석할 가능성이 있습니다. 빈값과 좌표 범위 검증을 추가하고 행정구역/반경 조회를 별도 테스트해야 합니다.
3. **비동기 결과와 입력 변경:** 기존 공공데이터·AI 요청 중 사용자가 입력을 바꿀 경우 결과가 이전 입력 기준일 수 있습니다. 요청 식별자·취소 또는 입력 잠금 등 최소 수정이 필요합니다.
4. **외부 응답 대기와 운영 상태:** 실제 외부 서비스·키·쿼터·응답시간을 호출 검증하지 않았습니다. 명시적 timeout과 오류 안내 검토가 필요합니다. 실제 비용 발생 테스트는 승인을 받아 제한된 횟수로 진행합니다.
5. **상태 보존:** 새로고침 이후 복구는 구현되어 있지 않습니다. 영속 저장이 필요하면 개인정보 보관 범위부터 합의한 뒤 별도 구현합니다.
6. **배포 파일 범위:** `.vercelignore`를 추가했지만 Git 연동 실제 빌드 산출물까지 검증한 것은 아닙니다. 승인된 Preview 단계에서 백업·도구·문서의 공개 여부를 확인해야 합니다. 구형 리소스는 참조를 제거했지만 파일은 복구를 위해 남겨두었습니다.
7. **브랜드·문의 자료:** 공식 색상값·로고·확정 세계관·활동 자료·공개 문의 채널이 필요합니다. 앱 상용 기능과 브랜드 IP 활동을 이미 제공 중인 것으로 확대 표현하지 않습니다.

## 7. 다음 개발 및 배포 순서
