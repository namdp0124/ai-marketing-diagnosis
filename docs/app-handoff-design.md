# YE-G 1.0 장기 진단 기록과 예지 진단 코드

웹에서 완료한 진단에 소유자가 있는 기록을 만들고, 앱에서 해당 기록을 조회할 수 있게 한다. 진단 코드는 기록을 찾기 위한 식별자이며 조회·수정·삭제 권한은 검증된 소유자 계정에서 확인한다. 화면에는 현재 ‘앱 연동 준비 중’이 표시된다. 이번 브랜치의 SQLite 프로토타입은 합성 데이터 검증용이며 Vercel의 배포 제외 디렉터리인 `tools/`에 있다.

## 코드와 소유권

| 값 | 역할과 수명 |
| --- | --- |
| 내부 기록 ID | 서버가 생성한 무작위 UUID v4. 기본 진단과 AI 실행안을 연결하는 키. 앱의 미션·개선 기록이 참조할 수 있다. |
| 예지 진단 코드 | CSPRNG 16바이트를 소문자 16진수 32자리로 표현하고 네 자리씩 구분해 표시한다. 복사한 코드는 구분자와 대소문자를 정규화한다. DB 고유 제약이 충돌을 막고 서버가 다시 생성한다. |
| 소유자 ID | 이메일 대신 인증 서비스의 고정 주체를 내부 UUID에 매핑한다. 웹·앱에서 같은 주체에 연결된 세션을 검증한다. 다른 로그인 방식끼리 연결하려면 두 자격 증명을 재확인하는 별도 절차가 필요하다. |
| 저장 식별자 | 확정된 진단 스냅샷이 갖는 UUID를 소유자와 묶어 저장 재시도를 식별한다. 기존 저장과 내용이 다르면 충돌로 응답한다. 사용자 입력이 바뀌어 새 진단을 저장하면 새 기록과 코드가 생성된다. |

같은 기록은 다시 저장하거나 AI 실행안을 추가해도 같은 코드를 갖는다. 코드 자체의 자동 만료나 복원 횟수 제한은 없다. 저장된 기록의 조회 가능 기간은 고지·동의한 데이터 보관 정책을 따른다. 복원 뒤에도 원기록이 유지되고, 같은 소유자가 다시 열 수 있다. 분실 시 로그인 후 다시 복사할 수 있다. 유출이 의심되면 본인 확인 후 코드를 회전하고 이전 코드를 폐기한다. 회전 전후의 기록 ID와 기존 앱 연결은 동일하다.

DB에는 코드 검색용 HMAC-SHA-256과 다시 복사할 때 사용할 AES-256-GCM 암호문을 저장한다. 암호화와 검색에는 독립된 서버 키를 쓴다. 스냅샷과 AI 원문 역시 별도의 암호문으로 저장하고 인증 데이터에 기록 ID·소유자·필드를 결합한다. 운영에서는 KMS의 키 버전을 기록해 활성 코드의 검색 인덱스를 재키잉하고 저장된 암호문을 새 키로 회전한다. HTTPS POST 본문으로 코드를 받아 URL, 로그, 분석 이벤트 및 캐시에 코드·원문을 남기지 않는다.

## 웹·앱 데이터 계약 v1

| 필드 | 자료형과 내용 |
| --- | --- |
| `schemaVersion`, `diagnosisVersion` | `1`과 `ye-g-1.0`. 배포 전 확정할 진단 규칙 버전을 함께 고정한다. |
| `profile`, `operations` | 업종·지역·운영 형태·운영 기간·고객층·판매 채널과 주변 상황·목표 선택값. |
| `answers` | 기존 문항 ID 12개에 대응하는 1–5 원답변. 역채점 문항도 사용자의 선택값을 보존한다. |
| `result` | 산출 시점의 전체·영역별 점수, 유형, 주요 개선 영역의 키·이름·점수. |
| `basicReport`, `recommendations` | 개인 식별 정보를 끌어오지 않는 버전별 기본 실행 리포트와 추천 방향. 프로토타입은 기존 진단 유형·점수·개선 항목과 고정 문구를 결합한다. |
| `aiReport` | 별도 동의가 있을 때 저장하는 AI 원문, 원문 생성 시각, 기록에 반영한 수정 시각. 미생성 또는 미동의 상태는 `null`이다. |
| 기록 메타데이터 | 기록 ID, AI 변경 리비전, 보관 종료 시각, 앱에 최초 연결한 시각. 동의의 범위·버전·시각은 서버에서 별도 관리한다. |

매장명·상세 주소·연락처·좌표·자유 입력과 공공데이터 조회 원문은 기본 기록에서 제외한다. 기존 화면·TXT에 자유 입력을 반영하는 맞춤 문구는 그대로 보존하며, 기본 스냅샷에서는 자유 입력을 참조하지 않는 보고서를 사용한다. 생산 API에서 서버가 버전별 점수 규칙으로 제출값을 검증하고, 수정되지 않은 현재 진단의 AI 결과만 해당 기록에 붙일 수 있도록 생성 당시 스냅샷과 연결한다. AI 저장에는 기본 저장과 분리된 동의와 원문 검토가 필요하다. 개인 식별 정보가 감지되면 원문 저장을 보류하며, 정규식만으로 이름이나 주소를 모두 식별할 수 있다고 가정하지 않는다.

기존 웹 진단은 탭 메모리와 TXT·복사·인쇄로 동작한다. 이전 이어하기 Preview는 발급 기능을 제공하지 않았으므로 이전 코드를 이전할 필요가 없다. 앱은 검증된 버전별 계약에서 저장된 점수와 결과를 읽고, 웹 계산 로직을 복제하거나 AI를 다시 호출할 필요가 없다. 다음 버전의 필드는 버전별 디코더와 명시적 마이그레이션으로 처리한다.

## 서버와 앱의 흐름

1. 웹에서 본인 인증 후 확정 진단과 기본 저장 동의를 제출한다. 서버가 소유권·스냅샷과 동의 버전을 확인하고, 기록과 코드를 한 트랜잭션으로 발급한다. UI에서 본인 코드 복사, 저장 항목 보기, AI 삭제, 코드 회전, 기록 삭제를 제공한다.
2. AI 생성은 기존 경로로 처리한다. 별도 저장 동의 후 현재 기록의 리비전과 생성 당시 스냅샷을 확인해 원문을 추가한다. 중복·오래된 갱신에는 상태를 재조회하도록 안내한다. 철회는 AI 암호문을 제거하고 리비전을 올려 이전 요청의 재반영을 막는다.
3. 앱 실행 후 로그인하고 코드와 인증 세션을 복원 전용 HTTPS POST로 전송한다. 인증 토큰의 서명·발급자·대상·만료를 확인하고, 코드가 찾은 기록의 소유자가 서버에서 해석한 주체인지 검사한다. 성공 시 기록을 앱 계정에 연결하고 기존 AI 원문을 반환한다. 계정 상태와 소유권을 조회마다 확인한다.
4. 복원 경로에 계정과 신뢰할 수 있는 네트워크 기준의 실패 횟수 제한을 둔다. 운영 초기값은 계정 1분당 5회, 네트워크 10분당 20회를 제안한다. 오류 응답은 미등록·폐기·타인 소유 코드 모두 동일하게 처리한다. 발급·재발급·삭제는 인증과 CSRF 방어, 짧은 재인증을 적용한다. 횟수 제한은 앱 이어하기 경로에만 적용한다.

프로토타입의 계정 인자는 인증 미들웨어의 결과를 모사한다. 배포용 토큰 검증, 분산 시도 제한, KMS와 저장소 연결, UI 발급과 복원 API는 운영 활성화에 필요한 후속 작업이다. 제안 API는 저장, 코드 복사·회전, AI 추가·철회, 복원, 삭제를 분리한다. 클라이언트가 넘긴 소유자 ID, 동의 버전, 보관 종료 시각을 그대로 신뢰하지 않는다.

## 데이터 보관과 삭제

초기 안으로 **저장일 기준 36개월** 보관을 제안한다. 앱 출시가 늦어지거나 장기 미사용 상태이면 종료 전에 앱 연동 상태와 기간을 알리고, 이용자가 연장에 동의하거나 다운로드·삭제를 선택할 수 있게 한다. 조회나 로그인만으로 기간이 자동 연장되지는 않는다. 저장 전 목적·항목·기간·삭제법·거부 시 영향을 설명하고 기본 저장과 AI 원문 저장 동의를 분리한다. 운영자 결정으로 확정할 사항은 36개월 채택 여부, 안내 연락 방식, 연장 절차와 처리방침이다.

철회·삭제 요청, 동의한 기간 종료, 서비스 종료 시 조회를 차단하고 운영 DB의 기록·코드·AI·앱 연결을 제거한다. 앱의 연관 기록도 소유권과 동의 범위에 따라 삭제·접근 차단한다. 과거 백업에서 삭제 기록이 되살아나지 않도록 운영 환경에서는 개인정보 없는 기록 식별자 기반의 삭제 원장을 복구 절차에 적용하고, 보안 보관 창이 끝나면 백업과 원장을 파기한다. 저장 재시도에 의한 재생성도 막도록 저장 요청의 서명을 원래 승인 범위·기간에 묶는다. 별도 법적 보존이 필요한 자료는 목적·기간을 분리하고 서비스 조회 경로에서 제외한다. 사전 고지와 파기 기준은 적용 시점의 개인정보 처리방침과 법령으로 확인한다. ## 저장소와 비용

1.0 전용 Neon Postgres가 우선 후보다. Vercel Node 런타임에서 풀링 연결을 사용하고, 기록·코드 고유성·동의·앱 연결을 원자적으로 처리한다. 비공개 DB와 접근 권한이 제한된 서버 역할을 사용한다. 별도 Supabase도 Postgres와 인증을 함께 검토할 때의 후보로 두고, 2.0 저장소·키와 권한을 공유하지 않는다. Preview에는 합성 데이터만 사용한다. 내구성, 배포 리전·국외 처리 여부, 키 접근 권한, 백업 창, 서비스 종료 시 파기 계획은 실제 데이터 저장 전에 확정한다. [Vercel 저장소 안내](https://vercel.com/docs/storage)

2026-11-17 확인한 공개 요금 기준으로 Neon Launch는 컴퓨트 CU-hour당 USD 0.106, 저장 GB-month당 USD 0.35, 시점 복원 이력 GB-month당 USD 0.20이다. 월 10–50 CU-hours, DB와 이력 각각 0.25 GB-month를 가정하면 해당 항목의 합계는 약 **월 USD 1.20–5.44**다. Supabase Pro 공개 기본가는 **월 USD 25부터**다. Vercel·인증·KMS·추가 백업·전송·세금은 별도이며, 실제 청구는 사용량, 리전, 구입 경로와 정책에 따라 달라진다. 이번 변경으로 저장소를 개설하거나 요금을 발생시키지 않는다. [Neon 요금표](https://neon.com/pricing) · [Supabase 요금표](https://supabase.com/pricing)

운영 활성화 전에 승인할 항목은 전용 저장소와 예산, 동일 소유자를 웹과 앱에서 검증할 인증 방식, 보관·연장·삭제·백업 정책, 기본 저장과 AI 저장에 쓰는 동의 문구다.

## 검증 범위

Node.js 24에서 `node tests/app-handoff-records.mjs`를 실행한다. 운영 진단 로직으로 만든 합성 데이터와 임시 SQLite 파일을 사용한다. 최초 저장과 재시도, AI 추가, 2년 뒤 같은 코드로 복원, 다른 계정·위조 코드·암호문 변조 차단, 충돌 시 재생성과 실패 시 되돌리기, 코드 회전, AI 철회, 기록 삭제와 보관 종료를 검사한다. 테스트 파일은 실행 종료 시 삭제되며 배포 API나 실제 OpenAI·소상공인365 호출이 필요하지 않다.
