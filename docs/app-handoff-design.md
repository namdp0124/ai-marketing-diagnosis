# YE-G 1.0 앱에서 이어하기 설계

이번 UI에서는 ‘앱 연동 준비 중’과 저장 예정 범위를 안내한다. 현재 진단은 탭 메모리에서 동작하며 TXT·복사·인쇄로 내보낼 수 있다. 이어하기에 필요한 서버 저장소는 1.0 프로젝트에 연결되어 있지 않다. 발급과 복원은 전용 저장소, 모바일 앱 인증 방식, 보관 기간과 동의 문구가 승인된 이후에 실행한다.

## 스냅샷 v1 제안

웹과 앱이 사용하는 버전이 명시된 JSON 계약이다. 웹의 기존 AI 요청 객체나 TXT 결과를 통째로 보내지 않는다. 서버는 허용 목록, 열거값, 답변 범위, 길이와 전체 용량을 검사한다.

| 필드 | 자료형과 출처 |
| --- | --- |
| `schemaVersion`, `diagnosisVersion` | 계약 버전 정수와 배포 시 고정한 진단 규칙 버전 |
| `profile` | 기존 선택 목록의 지역, 업종, 운영 형태·기간, 주 고객층, 판매 채널 |
| `answers` | 질문의 안정된 ID별 1–5 정수. 기본값을 포함한 현재 선택을 기록한다. 역채점 문항도 선택 원값을 보존한다. |
| `result` | 전체 및 영역별 점수, 진단 유형, 개선이 필요한 영역의 키와 점수 |
| `recommendations` | 개선 영역 키, 판매 채널별 실행 방향, 추천 지표. 버전별로 고정된 값 또는 안정된 키를 사용한다. |
| `aiReport` | 선택 필드. 별도 동의를 받은 현재 스냅샷의 AI 원문과 생성 시각. 원문 미리보기에서 연락처나 주소 등 개인 식별 정보를 제거하도록 안내하고, 선택 또는 응답의 기준 진단이 달라지면 다시 확인한다. |

매장명, 연락처, 상세 주소, 좌표, 자유 입력 메모, 위치 조회 원문은 기본 저장 범위에서 제외한다. 자유 입력을 반영하는 결과 요약과 광고 문구는 기본 스냅샷에 포함하지 않는다. 기존 점수 엔진의 결과는 원값을 유지하고, 동의 화면에서 서버로 전달할 항목을 확인할 수 있게 한다. 검증용 테스트는 실제 웹 진단에서 선택·원답변·점수·실행 방향을 읽고 합성 데이터의 스냅샷 구조와 대조한다.

## 발급과 복원

1. 웹의 동의 화면에서 저장 항목과 만료 시점을 확인한다. 기본 진단 저장 동의와 AI 원문 동의는 분리하고, 서버는 동의 버전·시각·범위를 기록한다.
2. 전용 비공개 트랜잭션 저장소를 사용하는 HTTPS 발급 API가 스냅샷을 저장한다. 16바이트 암호학적 난수를 읽기 쉬운 Base32 26자로 표현한다. 구분자 제거 후 정규화된 코드의 HMAC-SHA-256과 키 버전만 저장하고 고유 제약으로 충돌 시 새 난수를 발급한다. 평문 코드와 스냅샷은 로그·URL·분석 이벤트에 기록하지 않는다. 스냅샷은 서버 키로 암호화한다.
3. 앱이 자체 인증 세션으로 코드 검증·복원 API에 HTTPS POST 요청을 보낸다. 서버는 유효 기간과 버전을 확인하고, 사용 처리와 해당 앱 세션에 암호화된 복원 결과를 연결하는 작업을 하나의 트랜잭션으로 처리한다. 동일 세션은 짧은 시간 동안 별도 요청 ID로 전달 실패를 재시도할 수 있다. 코드는 첫 복원 이후 다시 사용할 수 없다.
4. 발급본은 최대 24시간 보관하는 안을 제안한다. 복원, 철회 또는 만료 시 임시 스냅샷을 삭제하고, 만료된 행은 별도 정리 작업으로 제거한다. 재시도용 복원 결과는 같은 앱 세션에만 최대 5분 보관한다. 앱에서 계정에 가져오는 단계는 별도 동의 및 앱의 삭제 정책을 따른다.
5. 발급한 웹 브라우저는 복원 코드와 별개인 서버 관리 세션으로 만료 전 삭제·철회를 할 수 있다. 이 세션은 HTTPS 전용 HttpOnly 쿠키로 관리한다. 발급·복원 경로에 세션별·네트워크별 시도 제한을 두고, 잘못되었거나 만료·사용된 코드는 같은 메시지로 응답한다. 기존 AI와 공공데이터의 호출 정책은 유지한다.

전용 저장소에는 만료가 있는 암호화 스냅샷, 수신 세션, 코드 HMAC과 동의 기록을 담는다. 비공개 Postgres는 고유 제약과 원자적 데이터 이전을 지원하는 후보이며, Redis를 선택한다면 TTL 외에도 원자적 소비와 재시도 처리를 검증해야 한다. YE-G 2.0 저장소와는 키, 데이터, 권한을 분리한다. 24시간과 5분은 설계상 제안값이며 실제 보관 정책은 저장소 연결 전 확정한다.
